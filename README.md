# ShieldCode 2.38 — проверка проектов

ShieldCode — бесплатный локальный сайт, который помогает найти возможные проблемы в файлах сайта или приложения и объясняет, с чего начать исправления. Есть аккаунты, история проверок, PDF-документы и копия проекта с ограниченными автоматическими правками. Загруженный код **не исполняется**.

В верхней панели можно выбрать русский или английский язык. Для вошедшего пользователя выбор сохраняется в его аккаунте и загружается при следующем входе, в том числе на другом устройстве. Для гостя язык запоминается только в этом браузере. Новые PDF-отчёты используют текущий язык.

## Быстрый запуск

### macOS / Linux
1. Установи Python 3.10 или новее.
2. Распакуй архив в папку.
3. Открой Terminal в папке проекта и выполни `./run_mac_linux.sh` (при необходимости сначала `chmod +x run_mac_linux.sh`).
4. Открой `http://127.0.0.1:8765` и создай аккаунт. При первом запуске рядом со старой версией программа перенесёт аккаунты и историю проверок, если найдёт прежнюю базу данных. Если порт занят другой копией, останови её через `Ctrl+C` в прежнем окне Терминала либо запусти `SHIELDCODE_PORT=8776 ./run_mac_linux.sh`. Старое имя настройки `CODESHIELD_PORT` тоже поддерживается.

### Windows
1. Установи Python 3.10+ и распакуй архив.
2. Запусти `run_windows.bat` или в PowerShell выполни `py server.py`.
3. Перейди на `http://127.0.0.1:8765`.

Остановить сервер: `Ctrl+C`. На первый запуск сторонние библиотеки не нужны.

Если онлайн-проверка сообщает, что Python не доверяет HTTPS-сертификату базы, обнови набор доверенных сертификатов:

```bash
python3 -m pip install --user --upgrade certifi
```

После установки останови сервер сочетанием `Ctrl+C` и запусти его снова. Проверка TLS остаётся включённой — ShieldCode не отключает её для обхода ошибки.

## Конфиденциальность

При проверке браузер передаёт выбранные файлы серверу ShieldCode; при локальном запуске сервер работает на компьютере пользователя. Файлы обрабатываются только на время проверки, не записываются в базу и не сохраняются в истории. В базе остаются имя файла или архива, дата, сводные результаты, рекомендации и фрагменты около найденных проблем. Сканер пытается скрывать распознанные секреты, но может пропустить некоторые из них. Для автоматической сверки библиотек с публичной базой OSV передаются только названия пакетов и точные версии.

История не удаляется автоматически. Самостоятельное удаление аккаунта и всех результатов пока не реализовано. Не загружайте конфиденциальные проекты, если сведения об их проверке не должны оставаться в базе.

## Функции

- 82 эвристических статических правила: сигналы для секретов, cookie-флагов, GitHub Actions, опасных операций и настроек инфраструктуры. Это не означает одинаковую глубину анализа для каждого языка: результат зависит от формата и контекста.

- Регистрация и вход; новые пароли хешируются PBKDF2-HMAC-SHA256 с уникальной случайной солью и 600 000 итерациями. Поддерживается вход для аккаунтов более раннего формата.
- Локальная база SQLite, сессии с случайными токенами, cookie HttpOnly/SameSite=Strict, защита Origin для запросов, ограничение частоты POST-запросов.
- CSP и базовые security headers, лимиты запроса/файла/числа файлов/распакованного ZIP, allowlist файлов, защита от path traversal и пропуск ZIP symlinks.
- Статические проверки секретов и приватных ключей, небезопасных DOM-вставок, `eval`/`new Function`, SQL/OS-команд, TLS, CORS, JWT-конфигурации, небезопасной десериализации, слабых криптографических хешей, YAML/XML, SSRF/open redirect, небезопасных cookie, source/config security signals.
- Проверки отдельных шаблонов в Dockerfile, `.dockerignore`, Kubernetes YAML, Terraform/HCL, GitHub Actions workflows, Python, PHP, C/C++, JVM, HTML/JS/TS/React/Vue и других поддерживаемых текстовых форматах.
- Jupyter Notebook: анализируются только ячейки кода после безопасного разбора JSON.
- Автоматическая онлайн-проверка поддерживаемых версий библиотек по базе известных уязвимостей. Для проверки отправляются только названия и версии библиотек; исходный код не отправляется. Временный запрос повторяется один раз, для Mac добавлена резервная проверка сертификатов `certifi`, а отчёт объясняет ошибки TLS-сертификата, DNS, тайм-аута, ограничения запросов и ответа сервера.
- В интерфейсе показываются последние 50 проверок. Исходные файлы не сохраняются, но база хранит названия загрузок, результаты и фрагменты рядом с находками. Старые записи не удаляются автоматически; в интерфейсе пока нет удаления аккаунта и истории. Подробности указаны в разделе «Конфиденциальность».
- План исправлений скачивается как PDF с таблицей: важность, название файла, строка и следующий шаг. Полный отчёт тоже скачивается как PDF.
- Понятный план действий после проверки: критические и высокие сигналы показаны первыми; карточки плана сразу фильтруют соответствующие находки.
- Интерфейс на русском языке для уровней риска и основных шагов. Бесплатная версия не требует оплаты или подписки.
- Один загруженный файл скачивается в исходном формате с пометкой «исправленный». ZIP-проект или набор файлов скачивается одним ZIP-архивом с сохранением структуры папок. Исходники пользователя не заменяются.
- ZIP-копия содержит только файлы проекта. План и подробности находятся в PDF-кнопках на странице результатов, поэтому внутри архива нет непонятных служебных отчётов.
- Автоматически вносятся безопасные механические правки: `yaml.load` → `yaml.safe_load`, включение проверки TLS, `debug=False` в `app.run`, CSRF-защита, флаги cookie `HttpOnly`/`Secure`, `filter='data'` для `tarfile.extractall`, `subprocess` без `shell=True` для простых команд, секреты `PASSWORD = "..."` в Python → переменные окружения, `innerHTML` с простым текстом → `textContent`, `rel` для `target="_blank"`, удаление монтирования `docker.sock` и `privileged: true` в YAML. Правки вносятся только в настоящий код (не в строки, комментарии, документацию и тесты). После исправления копия проверяется заново, а сайт показывает, сколько проблем исправлено и сколько осталось. Остальное (например, `eval`, `innerHTML` с переменной, SQL, CORS) описано в PDF и требует решения человека.
- На macOS PDF создаётся встроенной службой печати, устанавливать дополнительные библиотеки не нужно.

## Поддерживаемые форматы

Поддерживаются 157 расширений и 89 специальных имён файлов. Среди них HTML/XHTML, CSS/Sass/SCSS/Less, JavaScript/TypeScript/JSX/TSX, Vue/Svelte/Astro, Python/PHP/Ruby/Go/Java/C#/Kotlin/Scala/C/C++/Rust/Swift/Dart/Elm, SQL/GraphQL, Shell/PowerShell/Batch, Fortran, Pascal, Bicep, Rego, Cue, XML/JSON/JSONC/JSON5/YAML/TOML/INI/properties, Markdown/MDX/AsciiDoc/reStructuredText, Jupyter `.ipynb`, шаблоны Jinja/EJS/Twig/Handlebars, Dockerfile/Compose, Kubernetes YAML, Terraform/HCL, GitHub Actions/GitLab CI, dotenv/config files и dependency manifests/lock-файлы. Онлайн-проверка точных версий расширена на Bun `bun.lock` и Deno `deno.lock` в дополнение к npm/pnpm/yarn, Python, Cargo, Go, Composer, Gemfile, Maven, NuGet, Pub и Mix. Файлы до 2 MiB, общий запрос до 12 MiB, ZIP до 10 MiB, распакованный объём ZIP до 18 MiB, до 120 анализируемых файлов. Поддержка имени/формата не означает, что для него есть специализированные правила: многое проверяется общими правилами секретов и конфигураций.

## Онлайн-проверка зависимостей

При каждом сканировании сервис извлекает точные версии из поддерживаемых файлов со списком библиотек и отправляет их названия и версии в `https://api.osv.dev/v1/querybatch`. Исходный код не передаётся. Неизвестные и диапазонные версии пропускаются. Если онлайн-база недоступна, локальное сканирование всё равно завершается. Поиск не гарантирует обнаружить все уязвимости, а неподдерживаемый или некорректно разобранный файл со списком библиотек может быть пропущен.

## Автоисправления: осторожно

Автоматически исправляются лишь ограниченные, предсказуемые случаи. Перед заменой файлов проверь архив и изменения, запусти тесты и повтори анализ. Не существует безопасного универсального преобразования, которое автоматически чинит любые SQL-инъекции, XSS, контроль доступа или бизнес-логику без понимания проекта.

## Важные ограничения

Это учебный SAST-прототип, а не сертифицированный или полнофункциональный коммерческий сканер. Regex/эвристики дают ложные срабатывания и пропуски. Сайт не запускает DAST, не проверяет живой сервер, права доступа, бизнес-логику, все версии зависимостей, cloud accounts, бинарные форматы, SCA/SBOM полностью или все известные CVE. Он не заменяет code review, тесты, специализированные инструменты и профессиональный аудит. Число 0 совпадений или оценка 100/100 не означает гарантированную безопасность.

## Запуск тестов

```bash
python -m unittest discover -s tests -v
```

31 unit-тест проверяют базовые и дополнительные сигналы, redaction секретов, расширенные форматы, Docker/Kubernetes/Terraform/Jupyter, зависимости, ZIP path traversal и точечные автоисправления. Отдельно выполнен HTTP smoke-тест регистрации, сканирования, истории, отчёта и ZIP-исправлений.

## Безопасность при демонстрации

- По умолчанию сервер слушает только `127.0.0.1`; не открывай порт напрямую в интернет.
- Для публичного запуска потребуются HTTPS/reverse proxy, `SHIELDCODE_COOKIE_SECURE=1`, безопасные настройки хостинга, резервные копии, мониторинг, MFA/управление доступом, защита от CSRF в production-контексте и отдельный security review. Старое имя настройки `CODESHIELD_COOKIE_SECURE` тоже поддерживается.
- Не загружай чужие или конфиденциальные проекты в незнакомый сервис. Проверь каждый файл перед отправкой. Если секрет уже попал в публичное место, его нужно отозвать/сменить, а не только удалить из файла.
- База хранится в `data/codeshield.sqlite3`; имя файла оставлено для совместимости с прежними версиями. Не публикуй эту папку с данными пользователей.

## Что сканер не считает уязвимостью

Чтобы результат не засорялся, строки в следующих местах не попадают в отчёт (кроме ключей и токенов известных форматов — они ищутся везде):
- документация и переводы: `.md`, `.rst`, `.txt` (кроме файлов зависимостей), файлы в `i18n`/`locales`;
- папки и файлы тестов: `tests/`, `test/`, `fixtures/`, `test_*.py`, `*.test.js`, `*.spec.ts` и подобные;
- описания правил (`description`, `fix`, `example`, `pattern`, `title`) и закомментированные строки;
- строки с комментарием `shieldcode: ignore` (эта же строка) или `shieldcode: ignore-next-line` (строка выше). Используйте это осознанно: помеченная строка не проверяется и не исправляется.
